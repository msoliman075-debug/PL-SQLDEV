DATA FLOW DIAGRAM
================================================================================

AUTHORIZATION CHECK FLOW:
--------------------------

    1. User Accesses Page
           |
           v
    2. APEX Calls Authorization Scheme
           |
           v
    3. Package Function Called (e.g., is_page_authorized)
           |
           v
    4. Check Cache
           |
           +----> Cache Hit?  ──Yes──> Return Cached Result ──> [7]
           |
           No
           |
           v
    5. Query Database
           |
           +----> Check User Active?    ──No──>  Deny ──> [7]
           |      Check Super Admin?    ──Yes─>  Allow ──> [7]
           |      Check User Roles
           |      Check Role Permissions
           |      Check User Overrides
           |      Apply Temporal Rules
           |
           v
    6. Store in Cache
           |
           v
    7. Log to Audit (if enabled)
           |
           v
    8. Return TRUE/FALSE to APEX
           |
           v
    9. APEX Shows/Hides Object

    Time: ~1-5ms (cached) or ~10-50ms (database)

PERMISSION EVALUATION LOGIC
================================================================================

START
  |
  v
Is User Active and Not Locked?
  |
  +--NO--> DENY (User Inactive)
  |
YES
  |
  v
Is User Super Admin?
  |
  +--YES--> GRANT (Super Admin Bypass)
  |
NO
  |
  v
Does User Have Override Permission?
  |
  +--YES--> Is Override = 'Y'?
  |          |
  |          +--YES--> GRANT (User Override Grant)
  |          |
  |          +--NO--> DENY (User Override Deny)
  |
NO
  |
  v
Does User Have Role with Permission?
  |
  +--YES--> Is Permission Granted = 'Y'?
  |          |
  |          +--YES--> Check Temporal Validity
  |          |          |
  |          |          +--VALID--> GRANT (Role Permission)
  |          |          |
  |          |          +--EXPIRED--> Continue to Default
  |          |
  |          +--NO--> DENY (Explicit Role Denial)
  |
NO
  |
  v
Check Default Permission Policy
  |
  +--ALLOW--> GRANT (Default Allow)
  |
  +--DENY--> DENY (Default Deny)


TEMPORAL VALIDITY CHECK
================================================================================

For each permission/role assignment:

    SYSDATE >= effective_from
        AND
    (effective_to IS NULL OR SYSDATE <= effective_to)

Example Timeline:
-----------------
    effective_from      SYSDATE          effective_to
         |                 |                  |
    Jan 1, 2026      Jan 15, 2026        Mar 31, 2026
         |─────────────────✓─────────────────|
              VALID PERIOD

    Before Jan 1: NOT YET EFFECTIVE
    Jan 1 - Mar 31: ACTIVE
    After Mar 31: EXPIRED


CACHING MECHANISM
================================================================================

Cache Structure:
----------------
    Key: username|app_id|object_code|object_type|permission_type
    Value: BOOLEAN (TRUE = Granted, FALSE = Denied)
    Storage: PL/SQL Associative Array (Session Memory)
    Lifetime: Until cache timeout or clear_cache() called

Cache Flow:
-----------
    1. Authorization Request
           |
           v
    2. Generate Cache Key
           |
           v
    3. Check if Key Exists in Cache
           |
           +----> Exists? ──Yes──> Check Age
           |                        |
           |                        +--< Timeout ──> Return Cached Value
           |                        |
           |                        +--> Timeout ──> Continue to DB
           |
           No
           |
           v
    4. Query Database
           |
           v
    5. Store Result in Cache
           |
           v
    6. Return Result

Cache Benefits:
---------------
    • Reduces database calls by ~80-90%
    • Improves page load time
    • Reduces database load
    • Configurable timeout (default 300 seconds)

DISASTER RECOVERY
================================================================================

Critical Data (Must Backup):
    • APEX_AUTH_ROLES
    • APEX_AUTH_USERS
    • APEX_AUTH_USER_ROLES
    • APEX_AUTH_OBJECTS
    • APEX_AUTH_ROLE_PERMISSIONS
    • APEX_AUTH_CONFIG

Recoverable Data:
    • APEX_AUTH_AUDIT_LOG (archive separately)
    • Views (can be recreated from script)
    • Package (can be recreated from script)

Recovery Procedure:
    1. Restore tables from backup
    2. Recreate package (@02 and @03)
    3. Recreate views (@06)
    4. Validate with test users


SECURITY ARCHITECTURE
================================================================================

Defense Layers:
---------------
    1. Account Status Check (is_active, is_locked)
    2. Super Admin Bypass (configurable)
    3. User-Level Overrides (explicit grant/deny)
    4. Role-Based Permissions (primary control)
    5. Temporal Validity (time-based access)
    6. Default Policy (fail-safe)
    7. Audit Trail (complete logging)

SQL Injection Prevention:
-------------------------
    • All queries use bind variables
    • No dynamic SQL with string concatenation
    • Parameterized package calls

Data Integrity:
---------------
    • Foreign key constraints
    • Check constraints
    • Unique constraints
    • NOT NULL constraints
    • Default values

Access Control:
---------------
    • Uppercase username normalization
    • Case-insensitive comparisons
    • Explicit permission grants required
    • No default "allow all" behavior
