     Prerequisites: Tables created

INSTALLATION VERIFICATION
================================================================================

After installation, verify with these queries:

1. Check all objects created:
   
   SELECT object_name, object_type, status
   FROM user_objects
   WHERE object_name LIKE 'APEX_AUTH%'
   ORDER BY object_type, object_name;
   
   Expected: 11+ objects (9 tables, 1 package, 10 views), all VALID

2. Check for compilation errors:
   
   SELECT name, type, line, position, text
   FROM user_errors
   WHERE name LIKE 'APEX_AUTH%'
   ORDER BY name, sequence;
   
   Expected: No rows returned

3. Check configuration:
   
   SELECT * FROM apex_auth_config;
   
   Expected: 4 rows (ENABLE_AUDIT_LOG, DEFAULT_PERMISSION, 
                     CACHE_TIMEOUT_SECONDS, SUPERADMIN_ROLE)

4. Check default roles:
   
   SELECT role_code, role_name FROM apex_auth_roles
   ORDER BY role_code;
   
   Expected: 5 roles (ADMIN, GUEST, MANAGER, SUPERADMIN, USER)

5. Check default permissions:
   
   SELECT permission_code, permission_type FROM apex_auth_permissions
   ORDER BY permission_code;
   
   Expected: 5 permissions (ADMIN, DELETE, EDIT, EXECUTE, VIEW)

SYSTEM REQUIREMENTS
================================================================================

Database:
  - Oracle Database 19c or higher (19.1+)
  - Oracle APEX 19.1 or higher installed
  - 10 MB database space (minimum)
  - 50 MB recommended for audit log growth

Privileges Required:
  - CREATE TABLE
  - CREATE SEQUENCE (for Oracle < 12c)
  - CREATE PROCEDURE
  - CREATE VIEW
  - EXECUTE on APEX_APPLICATION (granted by APEX installation)

Performance Requirements:
  - Keep statistics updated (DBMS_STATS)
  - Monitor audit log size
  - Consider partitioning audit log for high-volume systems

SUPPORT INFORMATION
================================================================================

For issues, consult in this order:

1. README.md - Common issues and quick solutions
2. 05_Implementation_Guide.txt - Detailed troubleshooting section
3. Query user_errors view for compilation errors
4. Review audit log for authorization failures
5. Check configuration settings

Common Issues:

Issue: Package won't compile
Solution: Verify APEX is installed, check user_errors

Issue: Authorization always fails
Solution: Check user exists, role assigned, object registered, permission granted

Issue: Changes don't take effect
Solution: Clear cache with clear_cache() procedure

Issue: Audit log not populating
Solution: Enable via set_config('ENABLE_AUDIT_LOG', 'Y')

MAINTENANCE SCHEDULE
================================================================================

Daily:
  - Monitor APEX_AUTH_V_RECENT_DENIALS for security issues

Weekly:
  - Review APEX_AUTH_V_EXPIRING_ROLES
  - Check for users without roles

Monthly:
  - Archive audit log older than 90 days
  - Update database statistics
  - Review and clean up unused objects
  - Verify all role assignments are still valid

Quarterly:

BACKUP RECOMMENDATIONS
================================================================================

Include these objects in database backups:
  - All APEX_AUTH_* tables
  - APEX_AUTHORIZATION_PKG package
  - APEX_AUTH_V_* views (optional, can be recreated)

Critical data for export:
  - APEX_AUTH_ROLES
  - APEX_AUTH_USERS
  - APEX_AUTH_USER_ROLES
  - APEX_AUTH_OBJECTS
  - APEX_AUTH_ROLE_PERMISSIONS
  - APEX_AUTH_CONFIG

Export command example:
  expdp user/pass TABLES=APEX_AUTH_ROLES,APEX_AUTH_USERS,APEX_AUTH_USER_ROLES,
        APEX_AUTH_OBJECTS,APEX_AUTH_ROLE_PERMISSIONS,APEX_AUTH_CONFIG
        DIRECTORY=backup_dir DUMPFILE=auth_backup.dmp
